# H5: GitHub だけで、公開版を変えずに Pixel 7a で試遊する方法(提案)

条件: Cloudflare・Netlify などの外部サービスは使わない。main と現在の Pages は上書きしない。
**この文書は設計だけで、公開用リポジトリの作成・Pages の設定変更・公開はまだ何もしていない(ユーザーの承認が必要)。**

## 現状の制約
- この repo の Pages は 1 つのサイトだけ(いまの公開版)。同じ repo の別ブランチを同時に公開することはできない。
- Actions の成果物(artifact)は zip で、スマホのブラウザからそのままは遊べない。

## 案(推奨順)
1. **試遊専用の別リポジトリ + Pages(推奨)**
   - 例: `gusk2020/vind-ving-playtest`(最初は private でも、Pages を使うなら public が必要な場合がある。設定はユーザーが選ぶ)。
   - この repo の Actions(`playtest-build.yml`、手動実行)が、選んだブランチをビルドして `dist/` を artifact にする → 別リポジトリへ push(専用の fine-grained token をユーザーが作る)→ そちらの Pages が公開。
   - 公開 URL が別になるので、現在の公開版は一切変わらない。ブランチを選べば H2〜H5 のどれでも試遊できる。
   - ユーザーの操作: (1) 別リポジトリを作る (2) token を作り、この repo の Secrets に登録 (3) Actions で「Run workflow」。
2. **Actions の artifact をダウンロード(コード変更のみ・承認不要)**
   - `playtest-build.yml` で artifact を作る。スマホには zip を開くアプリが必要で、ローカルサーバーがないと動かないため、実用性は低い(確認用)。
3. **Codespaces のポート転送**
   - ブラウザの Codespaces で `npm run build && npx vite preview` を動かし、ポートを共有する。URL は一時的で、Codespaces の利用枠を使う。手軽だが長続きしない。

## 試遊前に自動で確認しているもの(CI)
unit・sim・build・browser 1〜5(実タッチ含む)は PR ごとに通る。耐久(endurance)は main への push 時と手元で実行。

## Pixel 7a で試すこと(実機未確認のもの)
1. 片手(右/左)で上下の◎が出る、下の◎で急ブレーキ・旋回・微速前進、離すとゆっくり前進。
2. 足場へ飛ぶと◯が出る。◯が画面の外・後ろのときは画面の縁に小さな◯が出て、押すと着地が始まる。
3. 風あり(既定)で、看板・電柱・枝・岩・ベランダへの自動着地。追い風でも回り込んで入る。
4. 着地後、立つ・歩く(長い足場のみ)・端から降りる。
5. 雨のあとの水たまり、休むと羽づくろい、水辺で飲む・浴びる。
6. オート(4 方針)で数分、水辺へ行く・座る・飛び立つ。
7. 遠くの道路が点滅しない(昼・夕・夜)。
